## S2 修复尝试与根因重定位（M8-2 收尾）

**目标**：把 `linewidth_overestimate` 从 1.20× 压到 1.05× 以内。

### 尝试过的两种写法（均已回滚）

| 写法 | 结果 | 回归 |
|---|---|---|
| `area / 骨架长`（去掉 `major_axis` 兜底） | `linewidth_overestimate` 仍为 **1.2024×**（无变化） | `test_linewidth_relative_error[10.0]` 等 3 个用例失败 |
| 改用 `cleaned` 而非 `best_binary` 计算 | 仍为 1.2024× | 同上 |

**为什么没变化**：`major_axis` 从未成为分母的有效约束——本场景的骨架长（420 px）
始终大于 `minAreaRect` 长边，`max()` 取的就是骨架长。也就是说，
真正的偏差来自**骨架长本身**。

### 根因：形态学骨架的切角缺陷（实测数据）

| 量 | 值 |
|---|---|
| 二值面积（cleaned） | 2986 px² |
| `skimage.skeletonize` 骨架长 | **420 px** → `area/skel` = **7.11 px** |
| `skimage.thin` 骨架长 | **418 px** → 7.14 px |
| **S3 图边长度（几何真值链）** | **504 px** → `area/504` = **5.93 px**（合成图名义 6 px ✓） |

6 px 宽的笔画在 ≥90° 折弯处，形态学骨架会"切角"，把弧段长度吃掉约 **17%**。
换 `skeletonize` 或 `thin` 都一样——这是骨架算法的固有行为，不是实现 bug。

### 结论与后续

- **方案 A/B/C 全部否决**：A（端点延伸）治标不治本；B（依赖 S3 长度）违反阶段边界；
  C（折角计数补偿）对锯齿极其脆弱。
- **采用方案 D：距离变换（EDT）法**（用户决策，M8-3）：
  `全局线宽 = 2 × f(EDT)`，EDT 是纯局部几何属性，**在折角处不会切角**。
  PoC 见 `scripts/poc_edt_linewidth.py`。
- **依赖链**（M8-3 顺序不可颠倒）：
  S2 线宽 EDT 改造 → 搜索半径精准化 → S4 过渡区轨对配对干净 →
  曲率突变点信噪比提升 → 切点判据成功。
